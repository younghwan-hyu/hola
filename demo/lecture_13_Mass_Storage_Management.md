# 강의 13: Mass Storage Management (대용량 저장장치 관리)

- 원본: lecture_13_Mass_Storage_Management.pdf
- 과목: 운영체제 (Operating Systems), 한양대학교

## 물리적 디스크 구조 (Physical Disk Structure)

- 디스크 구성: 얇은 금속 플래터(platter)들 + 그 위를 떠서 움직이는 read/write 헤드. 스핀들(spindle)이 플래터를 회전.
- 디스크에서 읽으려면 지정해야 하는 것: cylinder #, surface #, sector #, transfer size, memory address.
- 전송 시간 구성: Seek time (헤드를 실린더로 이동) + Rotational delay (원하는 섹터가 헤드 아래로 회전해 올 때까지) + Transfer time.

## 디스크 구조 (Disk Structure)

- 디스크 드라이브는 논리 블록(logical block)들의 큰 1차원 배열로 주소가 매겨짐. 논리 블록은 전송의 최소 단위.
- 논리 블록의 1차원 배열이 디스크 섹터들로 매핑됨: 섹터 0은 최외곽 실린더의 첫 트랙의 첫 섹터. 매핑은 그 트랙을 따라, 그 실린더의 나머지 트랙들로, 그리고 최외곽에서 최내곽으로 실린더들을 통해 순서대로 진행 → 실제 제품마다 많이 다름!

## 디스크 스케줄링 (Disk Scheduling)

- 접근 시간의 두 주요 구성: Seek time (디스크 암이 헤드를 원하는 섹터가 있는 실린더로 옮기는 시간), Rotational latency (원하는 섹터가 헤드로 회전해 올 때까지의 추가 시간).
- Seek time을 최소화하는 것이 목표. Seek time ∝ seek distance.
- 디스크 대역폭 = 전송된 총 바이트 수 / (첫 요청부터 마지막 전송 완료까지의 총 시간).
- 예제 요청 큐 (실린더 0–199): 98, 183, 37, 122, 14, 124, 65, 67. 현재 헤드 위치: 53.

### FCFS

- 요청 순서대로 서비스. 예제에서 총 헤드 이동 640 실린더.

### SSTF (Shortest Seek Time First)

- 현재 헤드 위치에서 seek time이 최소인 요청을 선택.
- SJF 스케줄링의 일종 → 일부 요청의 기아(starvation) 가능. 예측 불가능한 성능.
- 예제에서 총 헤드 이동 236 실린더.

### SCAN (엘리베이터 알고리즘)

- 디스크 암이 한쪽 끝에서 시작해 반대쪽 끝으로 이동하며 요청을 서비스하고, 끝에 닿으면 방향을 반대로 바꿔 계속 서비스.
- 올라가면서 모든 요청 서비스, 그다음 내려오면서 서비스.
- 예제에서 총 헤드 이동 208 실린더.
- 문제: 최외곽/최내곽 트랙이 1번 서비스될 동안 안쪽 트랙들은 2번 서비스 → 불공평한 대기 시간.

### C-SCAN

- SCAN보다 균일한 대기 시간 제공.
- 헤드가 한쪽 끝에서 다른 쪽 끝으로 이동하며 서비스하고, 끝에 도달하면 돌아오는 길에는 아무 요청도 서비스하지 않고 즉시 처음으로 복귀.
- 실린더들을 마지막에서 처음으로 감기는 원형 리스트처럼 취급.
- 문제: 그 방향에 대기 요청이 없어도 계속 전진함.

### C-LOOK

- C-SCAN의 개선판: 계속 가기 전에 요청이 있는지 확인 (Look-for-Request).
- 암은 각 방향의 마지막 요청까지만 가고, 디스크 끝까지 가지 않고 즉시 방향을 바꿈.

### Arm Stickiness 문제

- SCAN, C-SCAN, SSTF에서 발생 가능: 한두 프로세스가 특정 트랙에 높은 접근율을 가지면 그 트랙에 대한 요청을 반복해 장치 전체를 독점할 수 있음 (예: 15, 15, 15, 15, ... 사이에 낀 6번 요청은 계속 밀림).

## 디스크 관리 (Disk Management)

- 물리적 포맷 (Physical formatting, Low-level formatting): 디스크 컨트롤러가 읽고 쓸 수 있는 섹터들로 디스크를 분할.
  - 각 섹터 = [header + data (일반적으로 512바이트) + trailer].
  - header/trailer에는 섹터 번호와 ECC가 있음 (컨트롤러가 사용).
  - 실린더마다 spare 섹터들이 bad block 대비용으로 예약됨.
- 파일을 담기 위해 OS는 자체 자료구조를 디스크에 기록해야 함:
  - 파티션(Partition): 디스크를 하나 이상의 실린더 그룹으로 분할. OS는 각 파티션을 독립된 디스크처럼 취급.
  - 논리적 포맷 (Logical formatting) = "파일 시스템 만들기": OS가 사용할 파일 시스템 자료구조 초기화.
- 부팅 (Power-up): ROM의 "small bootstrap loader"가 실행됨 — 유일한 임무는 부트 디스크의 섹터 0(boot block)을 로드하는 것. 섹터 0에는 "full bootstrap loader" 프로그램이 있고, 이것이 디스크에서 OS를 로드.

## RAID (Redundant Array of Inexpensive/Independent Disks)

- 많은 디스크를 관리해 단일 디스크처럼 보이게 하는 디스크 조직 기법:
  - 여러 디스크를 병렬로 사용해 고용량·고속 제공.
  - 데이터를 중복(redundant) 저장해 고신뢰성 제공 — 디스크가 고장 나도 데이터 복구 가능.
- N개 디스크 중 하나가 고장 날 확률은 특정 단일 디스크가 고장 날 확률보다 훨씬 높음. 예: MTTF 100,000시간(약 11년)인 디스크 100개 시스템의 MTTF는 1,000시간(약 41일) → 디스크가 많을수록 중복으로 데이터 손실을 막는 기법이 중요.

### 중복을 통한 신뢰성 향상

- Redundancy: 디스크 고장 시 잃은 정보를 재구성할 수 있는 추가 정보를 저장.
- 예: 미러링 (Mirroring, shadowing): 모든 디스크를 복제 — 논리 디스크 하나 = 물리 디스크 2개. 모든 쓰기는 양쪽에 수행, 읽기는 아무 쪽에서나. 한쪽이 고장 나도 데이터는 다른 쪽에 있음. 데이터 손실은 첫 디스크 고장 후 수리 전에 미러 디스크도 고장 날 때만 발생 (화재·건물 붕괴·전력 서지 같은 종속 고장 모드 제외하면 확률 극히 낮음).
- 평균 데이터 손실 시간(mean time to data loss)은 MTTF와 평균 수리 시간(mean time to repair)에 좌우. 예: MTTF 100,000시간, 수리 10시간이면 미러 쌍의 평균 데이터 손실 시간 = 500×10^6 시간 (약 57,000년).

### 병렬성을 통한 성능 향상

- 디스크 시스템 병렬성의 두 목표: (1) 작은 접근 여러 개를 로드 밸런싱해 처리량 증가, (2) 큰 접근을 병렬화해 응답 시간 감소 (스트라이핑으로 전송률 향상).
- Bit-level striping: 각 바이트의 비트들을 여러 디스크에 분산. 디스크 8개 배열이면 각 바이트의 비트 i를 디스크 i에 기록. 단일 디스크의 8배 속도로 읽을 수 있지만 seek/access 시간은 단일 디스크보다 나쁨 → 요즘은 거의 안 씀.
- Block-level striping: 디스크 n개일 때 파일의 블록 i가 디스크 (i mod n) + 1로 감. 서로 다른 블록 요청은 서로 다른 디스크에 있으면 병렬 실행 가능. 긴 블록 시퀀스 요청은 모든 디스크를 병렬 활용.

### RAID 레벨

- 스트라이핑 + 패리티 비트를 결합해 낮은 비용으로 중복 제공. 레벨마다 비용·성능·신뢰성이 다름.
- RAID 0: 블록 스트라이핑, 중복 없음. 데이터 손실이 치명적이지 않은 고성능 응용에 사용.
- RAID 1: 블록 스트라이핑 + 미러 디스크. 최고의 쓰기 성능. DB 로그 파일 저장 등에 인기.
- RAID 2: 비트 레벨 스트라이핑 + ECC 디스크.
- RAID 3: 바이트 레벨 스트라이핑 + 전용 패리티 디스크.
- RAID 4: 블록 인터리브 패리티 — N개 디스크의 대응 블록들에 대한 패리티 블록을 별도 디스크에 유지. 데이터 블록을 쓸 때 대응 패리티 블록도 계산해 패리티 디스크에 써야 함. 손상된 블록 값은 다른 디스크들의 대응 블록(패리티 포함)의 XOR로 복원. 독립적인 블록 쓰기마다 패리티 디스크에도 써야 해서 패리티 디스크가 병목.
- RAID 5: 블록 인터리브 분산 패리티 — 데이터와 패리티를 N+1개 디스크 모두에 분산. 예: 디스크 5개일 때 n번째 블록 집합의 패리티 블록은 디스크 (n mod 5) + 1에, 데이터 블록은 나머지 4개에 저장.

### RAID 레벨 선택

- 고려 요소: 금전 비용, 정상 동작 시 성능 (초당 I/O 수, 대역폭), 고장 중 성능, 고장 디스크 재구축(rebuild) 중 성능.
- RAID 0: 데이터 안전이 중요하지 않을 때만 (다른 소스에서 빨리 복구 가능한 데이터).
- 레벨 2와 3은 더 이상 안 씀: 비트/바이트 스트라이핑은 단일 블록 읽기에도 모든 디스크 접근을 강제해 디스크 암 이동을 낭비 (블록 스트라이핑인 4, 5는 회피).
- 레벨 4는 레벨 5에 포섭되어(subsumed) 안 씀. 결국 경쟁은 1 vs 5.
- 레벨 1이 레벨 5보다 쓰기 성능이 훨씬 좋음: 레벨 5는 블록 하나를 쓰는 데 최소 2 블록 읽기 + 2 블록 쓰기 필요, 레벨 1은 2 블록 쓰기만. → 로그 디스크처럼 갱신이 많은 환경엔 레벨 1.
- 레벨 1은 저장 비용이 더 높지만: 디스크 용량은 연 50%씩 급증하는 반면 접근 시간은 훨씬 덜 개선됨 (10년에 3배). I/O 요구량도 크게 증가 (웹 서버 등). 필요한 I/O 속도를 맞추려 디스크를 충분히 사면 여유 용량이 남는 경우가 많아 레벨 1의 추가 비용이 없는 셈이 되기도.
- 결론: 갱신률이 낮고 데이터가 큰 응용은 레벨 5, 그 외에는 레벨 1 선호.
