# 강의 7: Deadlocks (교착상태)

- 원본: lecture_7_Deadlocks.pdf
- 과목: 운영체제 (Operating Systems), 한양대학교

## 교착상태 문제 (The Deadlock Problem)

- 블록된 프로세스들의 집합에서, 각자가 자원을 하나씩 쥔 채 그 집합의 다른 프로세스가 쥔 자원을 얻으려고 기다리는 상황.
- 예 1: 시스템에 테이프 드라이브 2개. P1과 P2가 각각 하나씩 쥐고 서로 상대 것이 필요함.
- 예 2: 세마포어 A, B가 각각 1로 초기화. P0는 P(A); P(B); 순으로, P1은 P(B); P(A); 순으로 실행하면 교착상태 가능.

## 교착상태 특성화 (Deadlock Characterization) — 4가지 필요조건

교착상태는 다음 4가지 조건이 동시에 성립할 때 발생할 수 있음 (필요조건, necessary condition):

1. 상호 배제 (Mutual exclusion): 한 번에 한 프로세스만 자원을 사용할 수 있음.
2. 비선점 (No preemption): 자원은 그것을 쥔 프로세스가 작업을 완료한 후 자발적으로만 해제됨.
3. 점유와 대기 (Hold and wait): 최소 하나의 자원을 쥔 프로세스가 다른 프로세스가 쥔 추가 자원을 얻으려고 기다림.
4. 순환 대기 (Circular wait): 대기 프로세스 집합 {P0, P1, …, Pn}이 존재해 P0는 P1이 쥔 자원을, P1은 P2가 쥔 자원을, …, Pn−1은 Pn이 쥔 자원을, Pn은 P0가 쥔 자원을 기다림.

- 현실 세계 예: 교차로의 교통 교착 (traffic deadlock).

## 자원 할당 그래프 (Resource-Allocation Graph)

- 정점 집합 V와 간선 집합 E. V는 두 종류로 분할:
  - P = {P1, …, Pn}: 시스템의 모든 프로세스 집합.
  - R = {R1, …, Rm}: 시스템의 모든 자원 유형 집합 (자원 유형은 여러 인스턴스를 가질 수 있음).
- 요청 간선 (request edge): Pi → Rj (프로세스가 자원 인스턴스를 요청).
- 할당 간선 (assignment edge): Rj → Pi (자원 인스턴스가 프로세스에 할당됨).
- 기본 사실 (Basic Facts):
  - 그래프에 사이클이 없으면 → 교착상태 없음.
  - 그래프에 사이클이 있으면 → 자원 유형당 인스턴스가 1개뿐이면 교착상태. 인스턴스가 여러 개면 교착상태 가능성만 있음 (사이클이 있어도 교착상태가 아닐 수 있음).

## 교착상태 처리 방법 (Methods for Handling Deadlocks)

1. 시스템이 절대 교착상태에 들어가지 않도록 보장 — 예방(prevent), 회피(avoid).
2. 교착상태에 들어가는 것을 허용한 뒤 복구 — 탐지(detection) 후 recovery.
3. 문제를 무시하고 교착상태가 발생하지 않는 척함 — UNIX를 포함한 대부분의 운영체제가 사용.

## 교착상태 예방 (Deadlock Prevention)

요청 방식을 제한해 4가지 필요조건 중 하나라도 성립하지 않게 만듦:

- 상호 배제: 공유 가능한(sharable) 자원에는 필요 없음. 본질적으로 공유 불가능한 자원에는 성립할 수밖에 없음 (강제 불가).
- 점유와 대기: 프로세스가 자원을 요청할 때 다른 자원을 쥐고 있지 않음을 보장. 방법: 실행 시작 전에 모든 자원을 요청·할당받게 하거나, 자원이 하나도 없을 때만 요청 허용 (all or nothing). 단점: 자원 활용률 낮음, 기아 가능.
- 비선점: 어떤 자원을 쥔 프로세스가 즉시 할당될 수 없는 자원을 요청하면, 현재 쥔 모든 자원을 해제. 선점된 자원은 그 프로세스가 기다리는 자원 목록에 추가되고, 이전 자원과 새 자원을 모두 다시 얻을 수 있을 때만 재시작.
- 순환 대기: 모든 자원 유형에 전순서(total ordering)를 부여하고, 각 프로세스가 번호 증가 순서로만 자원을 요청하도록 요구.
- 공통 단점: 자원 활용률 저하와 시스템 처리량 감소.

## 교착상태 회피 (Deadlock Avoidance)

- 시스템에 추가적인 사전(a priori) 정보 필요. 가장 단순하고 유용한 모델: 각 프로세스가 필요할 수 있는 각 자원 유형의 최대 개수를 미리 선언.
- 회피 알고리즘은 자원 할당 상태를 동적으로 검사해 순환 대기 조건이 절대 생기지 않도록 보장.
- 자원 할당 상태 = 가용/할당된 자원 수 + 프로세스들의 최대 요구량.

### 안전 상태 (Safe State)

- 프로세스가 가용 자원을 요청하면, 시스템은 즉시 할당해도 시스템이 안전 상태(safe state)로 남는지 결정해야 함.
- 순서 <P1, P2, …, Pn>이 안전(safe)하다는 것: 각 Pi에 대해, Pi가 앞으로 요청할 수 있는 자원이 "현재 가용 자원 + j<i인 모든 Pj가 쥔 자원"으로 충족될 수 있다는 것.
  - Pi의 자원 요구가 즉시 충족 안 되면 모든 Pj(j<i)가 끝날 때까지 대기하면 됨. Pj가 끝나면 Pi가 자원을 얻어 실행하고 반환 후 종료. Pi가 종료하면 Pi+1이 자원을 얻고… 반복.
- 시스템에 모든 프로세스의 안전 순서(safe sequence)가 존재하면 안전 상태.
- 기본 사실: 안전 상태면 교착상태 없음. 불안전(unsafe) 상태면 교착상태 가능성 있음 (모든 프로세스가 최대 자원을 동시에 요청하는 경우).
- 회피 = 시스템이 절대 불안전 상태에 들어가지 않도록 보장: "요청을 들어줘도 안전 상태면 허가하고, 아니면 허가하지 않는다."

### 회피 알고리즘 A: 자원 유형당 인스턴스 1개 — 자원 할당 그래프 알고리즘

- claim edge (예약 간선): Pi → Rj 점선 — Pi가 Rj를 요청할 수도 있음을 표시. 자원은 시스템에서 사전에 claim되어야 함.
- 프로세스가 실제 요청하면 claim edge가 request edge로 전환. 자원이 할당되면 request edge가 assignment edge로 전환. 자원이 해제되면 assignment edge가 다시 claim edge로 복귀.
- 알고리즘: Pi가 Rj를 요청할 때, request edge를 assignment edge로 바꿔도 그래프에 사이클이 생기지 않을 때만 허가. (사이클 없음 → 안전 → 허가 / 사이클 → 불안전 → 거부)

### 회피 알고리즘 B: 자원 유형당 인스턴스 여러 개 — 은행원 알고리즘 (Banker's Algorithm)

- 각 프로세스는 최대 사용량을 사전에 선언해야 함. 요청 시 기다려야 할 수 있음. 모든 자원을 받으면 유한 시간 안에 반환해야 함.
- 자료구조 (n = 프로세스 수, m = 자원 유형 수):
  - Available (길이 m 벡터): Available[j]=k → 자원 Rj의 k개 인스턴스 가용.
  - Max (n×m 행렬): Max[i,j]=k → Pi는 Rj를 최대 k개 요청 가능.
  - Allocation (n×m 행렬): Allocation[i,j]=k → Pi에 현재 Rj가 k개 할당됨.
  - Need (n×m 행렬): Need[i,j] = Max[i,j] − Allocation[i,j] → Pi가 앞으로 Rj를 k개 더 필요로 할 수 있음.

#### 안전성 알고리즘 (Safety Algorithm)

1. Work(길이 m), Finish(길이 n) 벡터 초기화: Work := Available, Finish[i] = false (모든 i).
2. 다음을 만족하는 i를 찾음: (a) Finish[i] = false, (b) Need_i ≤ Work. 없으면 4단계로.
3. Work := Work + Allocation_i; Finish[i] := true; 2단계로 반복.
4. 모든 i에 대해 Finish[i] = true면 시스템은 안전 상태.

#### 자원 요청 알고리즘 (Resource-Request Algorithm, 프로세스 Pi)

- Request_i = Pi의 요청 벡터. Request_i[j]=k는 Rj를 k개 원함.
1. Request_i ≤ Need_i 인지 확인. 아니면 오류 (최대 요구량 초과).
2. Request_i ≤ Available 인지 확인. 아니면 Pi는 대기 (자원 없음).
3. 할당한 셈 치고 상태를 수정 (pretend): Available := Available − Request_i; Allocation_i := Allocation_i + Request_i; Need_i := Need_i − Request_i.
   - 그 상태가 안전하면 → 실제로 할당.
   - 불안전하면 → Pi는 대기하고 이전 자원 할당 상태 복원.

#### 은행원 알고리즘 예제

- 프로세스 5개 (P0–P4), 자원 유형 3개: A(10개), B(5개), C(7개). 시각 T0의 스냅샷:

| 프로세스 | Allocation (ABC) | Max (ABC) | Need (ABC) |
|---|---|---|---|
| P0 | 0 1 0 | 7 5 3 | 7 4 3 |
| P1 | 2 0 0 | 3 2 2 | 1 2 2 |
| P2 | 3 0 2 | 9 0 2 | 6 0 0 |
| P3 | 2 1 1 | 2 2 2 | 0 1 1 |
| P4 | 0 0 2 | 4 3 3 | 4 3 1 |

- Available = (3, 3, 2). 순서 <P1, P3, P4, P2, P0>가 안전성 기준을 만족하므로 시스템은 안전 상태.
- 이어서 P1이 (1,0,2)를 요청하면: Request ≤ Available ((1,0,2) ≤ (3,3,2)) 확인 → 가할당 후 Allocation P1=(3,0,2), Need P1=(0,2,0), Available=(2,3,0). 안전성 알고리즘을 돌리면 <P1, P3, P4, P0, P2>가 만족 → 허가.
- 추가 질문: P4의 (3,3,0) 요청은 허가 가능한가? (Available 부족으로 대기) P0의 (0,2,0) 요청은 허가 가능한가? (불안전 상태가 되므로 거부)

## 교착상태 탐지 (Deadlock Detection)

- 시스템이 교착상태에 들어가는 것을 허용하고, 탐지 알고리즘과 복구 방법을 운용.
- 경우 A — 자원 유형당 인스턴스 1개: wait-for 그래프 유지. 노드는 프로세스, Pk → Pj는 Pk가 Pj를 기다림을 의미 (자원 할당 그래프에서 자원 노드를 제거해 얻음). 사이클을 찾는 알고리즘을 주기적으로 호출. 그래프 사이클 탐지는 O(n²) 연산 (n = 정점 수).
- 경우 B — 자원 유형당 인스턴스 여러 개: 교착상태 탐지 알고리즘 사용.
  - 자료구조: Available (길이 m), Allocation (n×m), Request (n×m — request[i,j]=k면 Pi가 Rj를 k개 더 요청 중).

### 탐지 알고리즘 (Detection Algorithm)

1. Work := Available로 초기화. 각 i에 대해 Allocation_i ≠ 0이면 Finish[i] = false, 아니면 true.
2. 다음을 만족하는 i를 찾음: (a) Finish[i] = false, (b) Request_i ≤ Work. 없으면 4단계로.
3. Work := Work + Allocation_i; Finish[i] := true; 2단계로.
4. 어떤 i에 대해 Finish[i] = false면 시스템은 교착상태. Finish[i] = false인 프로세스 Pi가 교착상태에 빠진 것.

- 예: 프로세스 5개 (P0–P4), 자원 A(7), B(2), C(6). Allocation: P0=010, P1=200, P2=303, P3=211, P4=002. Request: P0=000, P1=202, P2=000, P3=100, P4=002. Available=(0,0,0). 순서 <P0, P2, P3, P1, P4>로 모든 i에서 Finish[i]=true → 교착상태 아님. (만약 P2가 C를 하나 더 요청하면 교착상태 발생.)
- 복잡도: O(m × n²). m=n이면 O(n³).
- 탐지 알고리즘 호출 주기 문제: 요청마다? (오버헤드 큼) / 즉시 할당되지 못한 요청마다? / 주기적으로? (교착 확률이 낮으면).

## 교착상태 복구 (Recovery from Deadlock)

### 프로세스 종료 (Process Termination)

- 교착상태의 모든 프로세스를 중단(abort)하거나, 사이클이 없어질 때까지 한 번에 하나씩 중단.
- 중단 순서 선택 기준: 프로세스 우선순위, 지금까지 계산한 시간과 완료까지 남은 시간, 사용한 자원, 완료에 필요한 자원, 종료해야 할 프로세스 수, 대화형인지 배치인지.

### 자원 선점 (Resource Preemption)

- 희생자(victim) 선택: 비용 최소화.
- 롤백(Rollback): 안전한 상태로 되돌린 후 그 상태에서 프로세스 재시작.
- 기아(Starvation): 같은 프로세스가 반복해서 희생자로 뽑힐 수 있음 → 비용 요소에 롤백 횟수를 포함시켜 방지.

## 회피 vs 탐지 (Avoidance vs Detection)

- 회피 (Avoidance): 프로세스들이 최악으로 행동한다고 가정 — 모든 프로세스가 동시에 최대 자원을 요구하는 최악의 경우를 가정하고, 그래도 안전 순서가 있을 때만 자원 할당. 자원을 낭비할 수 있음.
- 탐지 (Detection): 모든 프로세스가 휴면(dormant)한다고 가정 — 더 이상 자원을 요청하지 않을 것이라는 최선의 경우를 가정하고, 현재 상태만으로 교착상태를 탐지.
