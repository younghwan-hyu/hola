## 프레임 할당 (Allocation of Frames)

- 여러 프로세스에게 페이지 프레임을 어떻게 할당할 것인가?
- 각 프로세스는 최소한의 페이지 수가 필요:
  - HW 측면: IBM 370 — SS MOVE 명령어 처리에 6페이지 필요. 명령어가 6바이트라 2페이지에 걸칠 수 있고, from 처리에 2페이지, to 처리에 2페이지.
  - SW 측면: Loop 내의 페이지는 한꺼번에 할당되는 것이 유리함. 그렇지 않으면 매 loop마다 page fault 발생 — CPU/disk 부하의 심한 불균형.
- 두 가지 주요 할당 방식: 고정 할당 (fixed allocation), 우선순위 할당 (priority allocation).

### 고정 할당 (Fixed Allocation)

- 균등 할당 (Equal allocation): 각 프로세스에 같은 수의 프레임. 예: 프레임 100개, 프로세스 5개 → 각 20페이지.
- 비례 할당 (Proportional allocation): 프로세스 크기에 비례해 할당.
  - s_i = 프로세스 p_i의 크기, S = Σs_i, m = 총 프레임 수, a_i = p_i에 대한 할당 = (s_i / S) × m.
  - 예: m = 64, s1 = 10, s2 = 127 → a1 = 10/137 × 64 ≈ 5, a2 = 127/137 × 64 ≈ 59.

### 우선순위 할당 (Priority Allocation)

- 크기 대신 우선순위를 사용한 비례 할당.
- 높은 우선순위 프로세스에 더 많은 메모리를 주어 일찍 끝나게 함 (I/O 감소 → 'waiting' 상태 시간 감소 → 조기 종료).
- 프로세스 Pi가 페이지 폴트를 내면: 자신의 프레임 중에서 victim을 고르거나, 더 낮은 우선순위 프로세스의 프레임에서 victim을 고름.

### 전역 vs 지역 교체 (Global vs. Local Replacement)

- Global replacement: 모든 프레임 집합에서 교체 프레임 선택 — 한 프로세스가 다른 프로세스의 프레임을 뺏을 수 있음.
- Local replacement: 각 프로세스는 자신에게 할당된 프레임 집합 안에서만 선택.

## 스래싱 (Thrashing)

- 프로세스에 "충분한" 페이지가 없으면 페이지 폴트율이 매우 높아짐. 그 결과:
  - 낮은 CPU 활용률.
  - OS는 멀티프로그래밍 정도(MPD)를 올려야 한다고 판단.
  - 시스템에 또 다른 프로세스 추가 (MPD 상승) → 악순환.
- 스래싱 = 프로세스가 페이지를 스왑 인/아웃하느라 바쁜 상태. CPU는 대부분 유휴 — 낮은 처리량.
- 페이징이 동작하는 이유 — 지역성 모델 (Locality model): 프로세스는 한 지역성(locality)에서 다른 지역성으로 이동하며, 지역성들은 겹칠 수 있음.
- 스래싱이 발생하는 이유: (지역성의 크기 합) > (총 할당된 메모리 크기).

## 지역성 (Locality)

- 프로그램의 메모리 참조는 고도의 지역성을 가짐. 임의 시간 Δt 내에 프로그램의 일부분만을 집중적으로 참조.
- 시간 지역성 (Temporal Locality): 현재 참조된 메모리가 가까운 미래에도 참조될 가능성이 높음. 예: loop, subroutine, stack.
- 공간 지역성 (Spatial Locality): 하나의 메모리가 참조되면 주변 메모리가 계속 참조될 가능성이 높음. 예: 배열 순회(array traversal), 명령의 순차 실행.

## 워킹셋 모델 (Working-Set Model)

- Δ = working-set window = 고정된 수의 페이지 참조 (예: 명령어 10,000개).
- WS(t_i) = { t_i부터 t_i−Δ 구간에서 참조된 페이지들 }.
  - Δ가 너무 작으면 전체 지역성을 포괄하지 못함.
  - Δ가 너무 크면 여러 지역성을 포괄해버림.
  - Δ = ∞면 전체 프로그램을 포괄.
- WSS_i = 프로세스 P_i의 워킹셋 크기.
- D = Σ WSS_i = 총 요구 프레임 수. D > m이면 스래싱 (m = 총 가용 프레임 수).
- 정책: D > m이면 프로세스 중 하나를 중단(suspend).
- 워킹셋 모델의 의미: 프로세스에 WSS 이상의 메모리를 할당할 수 없으면 그 프로세스를 suspend → MPD(멀티프로그래밍 정도)를 결정. 즉 (WSS 전체 보장) 또는 (suspended) 중 택일.
- 페이지 P가 t_i에 WS(t_i)에 속하면 메모리에 유지(keep in memory), 안 속하면 메모리에서 제외(out of memory). 이 원칙에 따라 replace와 allocate를 결정 → 워킹셋 모델은 할당(allocation)과 교체(replacement)를 같이 결정함. 시간에 따라 할당 크기가 달라질 수 있음. WS(t_i)가 모두 보장되어야만 run, 아니면 suspend.

### 워킹셋 추적 (Keeping Track of the Working Set)

- 정확한 구현(매 참조마다 각 페이지의 최근 참조 시간을 Δ와 비교)은 너무 비쌈 (참조 시간 필드 공간 + 비교 시간).
- 근사: 인터벌 타이머 + reference bit.
- 예: Δ = 10K, 타이머 인터럽트를 5K 시간 단위마다. 페이지마다 메모리에 2비트 유지. 타이머 인터럽트 시 reference bit을 복사하고 리셋. 메모리의 비트 중 하나라도 1이면 → 그 페이지는 워킹셋에 속함.
- 완전히 정확하지 않은 이유: 참조가 구간 내 어느 시점에 일어났는지 모름. 개선: 10비트 + 1000 시간 단위마다 인터럽트.
- 남는 질문: 윈도우 크기(Δ)는 어떻게 정하나?

## 페이지 폴트 빈도 기법 (Page-Fault Frequency Scheme, PFF)

- "허용 가능한" 페이지 폴트율을 설정:
  - 실제 폴트율이 너무 낮으면 → 프로세스에서 프레임을 회수.
  - 실제 폴트율이 너무 높으면 → 프로세스에 프레임을 더 줌.
- 비교: Working set 기법은 페이지 참조 시마다 페이지 집합을 수정하지만, PFF 기법은 page fault 발생 시에만 페이지 집합을 수정.

## 가상 메모리의 다른 이점: 프로세스 생성

### Copy-on-Write (COW)

- 부모와 자식 프로세스가 처음에는 메모리의 같은 페이지들을 공유하게 함.
- 어느 한쪽이 공유 페이지를 수정할 때만 그 페이지가 복사됨.
- 수정된 페이지만 복사되므로 더 효율적인 프로세스 생성 가능.

### 메모리 매핑 파일 (Memory-Mapped Files)

- 디스크 블록을 메모리의 페이지에 매핑함으로써 파일 I/O를 일반 메모리 접근처럼 다룸.
- 파일은 처음에 요구 페이징으로 읽힘: 파일의 페이지 크기 부분이 파일 시스템에서 물리 페이지로 읽혀 들어옴. 이후의 읽기/쓰기는 일반 메모리 접근으로 처리.
- 파일 접근 단순화: read()/write() 시스템 콜 대신 메모리를 통해 파일 I/O.
- 여러 프로세스가 같은 파일을 매핑해 메모리의 페이지들을 공유할 수도 있음.

## 기타 이슈

### Prepaging (사전 페이징)

- 프로세스 시작 시 발생하는 대량의 페이지 폴트를 줄이기 위해, 참조되기 전에 필요할 페이지 전부/일부를 미리 로드.
- 사전 로드된 페이지가 사용되지 않으면 I/O와 메모리 낭비.
- s개 페이지를 prepage하고 그중 비율 α가 사용된다면: 절약한 s×α번의 페이지 폴트 비용 vs 불필요한 s×(1−α)개 페이지의 prepaging 비용 비교. α가 0에 가까우면 prepaging이 손해.

### 페이지 크기 (Page size)

- 페이지 크기 선택 시 고려사항: 내부 단편화(작을수록 유리), 페이지 테이블 크기(클수록 유리), 디스크 전송 효율 — seek/rotation vs. transfer (클수록 유리), I/O 연산 빈도, 지역성 개선 (작은 페이지가 필요한 정보만 격리).
- 추세: 더 큰 페이지 크기. CPU 속도·메모리 용량이 디스크 속도보다 빨리 개선되어 페이지 폴트의 (상대적) 페널티가 점점 더 커지고 있기 때문.

### TLB Reach

- TLB Reach = TLB에서 접근 가능한 메모리 양 = (TLB Size) × (Page Size).
- 이상적으로는 각 프로세스의 워킹셋이 TLB에 저장되어야 함. 아니면 TLB 미스가 많아짐.
- 페이지 크기 증가: 큰 페이지가 필요 없는 응용에서는 단편화 증가 가능.
- 여러 페이지 크기 제공: 큰 페이지가 필요한 응용만 단편화 증가 없이 큰 페이지 사용 가능.

### 프로그램 구조 (Program Structure)

- int data[128][128]; 각 행(row)이 페이지 하나에 저장된다고 하자. data용 빈 프레임 수 < 128 가정.
- 프로그램 1: `for (j = 0; j < 128; j++) for (i = 0; i < 128; i++) data[i][j] = 0;` → 열 우선 접근 → 128 × 128 = 16,384 페이지 폴트.
- 프로그램 2: `for (i = 0; i < 128; i++) for (j = 0; j < 128; j++) data[i][j] = 0;` → 행 우선 접근 → 128 페이지 폴트 (data용 프레임이 1개뿐이어도).

### I/O Interlock

- 페이지를 때때로 메모리에 고정(lock)해야 함.
- 장치에서 파일을 복사하는 데 사용 중인 페이지는 페이지 교체 알고리즘의 eviction 대상으로 선택되지 않도록 잠가야 함.
